## 🔑 API Keys

### الإصدار:
```
POST /api/admin/api-keys
Body: {
    name: 'Production Integration',
    scopes: ['read:sales', 'write:invoices'],
    expiresIn: '1y'  // أو 'never'
}

Response:
{
    keyId: 'k_123',
    key: 'nma_a1b2c3d4e5f6...40chars',  // مرة واحدة فقط!
    scopes: [...],
    expiresAt: '2027-05-14'
}
```

### الصيغة:
- prefix: `nma_`
- 40 hex chars
- مثال: `nma_a1b2c3d4e5f67890abcdef1234567890abcdef12`

### الاستخدام:
```bash
curl -H "Authorization: Bearer nma_..." https://aljassim.namainvist.com/api/products
```

### النموذج:
```prisma
ApiKey {
    id, name, keyHash  // SHA-256
    scopes: Json
    createdByUserId
    expiresAt
    lastUsedAt
    usageCount
    isActive
    
    @@unique([keyHash])
}
```

### الـ Scopes الـ Available:
```
read:sales, write:sales
read:purchases, write:purchases
read:inventory, write:inventory
read:customers, write:customers
read:employees, write:employees
read:reports
admin:webhooks
admin:settings
```

### Rate Limiting:
- per API key
- DEFAULT tier (120 req/min)
- Premium tier (1000 req/min)

## 🔗 Webhooks

### Subscribe:
```typescript
POST /api/webhooks/subscriptions
Body: {
    name: 'My Integration',
    url: 'https://my-app.com/webhook',
    events: ['INVOICE_CREATED', 'PAYMENT_RECEIVED'],
    description: 'For accounting sync'
}

Response: {
    id: 'wh_123',
    secret: 'whsec_abc...',  // للـ HMAC verification
    url, events, active: true
}
```

### الـ Events:
راجع `32-webhooks-events.md` للقائمة الكاملة.

### الـ Verification:
```typescript
// في الـ endpoint الخارجي:
import crypto from 'crypto';

app.post('/webhook', (req, res) => {
    const signature = req.headers['x-namasoft-signature'];
    const body = JSON.stringify(req.body);
    
    const expected = crypto
        .createHmac('sha256', WEBHOOK_SECRET)
        .update(body)
        .digest('hex');
    
    if (signature !== expected) {
        return res.status(401).send('Invalid signature');
    }
    
    // الـ payload صحيح
    const { event, data } = req.body;
    
    switch (event) {
        case 'INVOICE_CREATED':
            syncToAccountingSystem(data);
            break;
        // ...
    }
    
    res.status(200).send('OK');
});
```

### الـ Delivery Guarantees:
- **At-least-once delivery**
- Retry: 3 times, exponential backoff
- Idempotency: استخدم `X-NamaSoft-Delivery` (UUID) لمنع duplicates

## 🔄 Integration Patterns

### Pattern 1: Webhook-Driven (Push)
**الاستخدام:** Real-time updates
```
Source → Webhook → NamaInvest
```

### Pattern 2: Polling (Pull)
**الاستخدام:** Sources without webhooks
```
NamaInvest (cron) → API call → External
```

### Pattern 3: Two-Way Sync
**الاستخدام:** Bi-directional updates
```
NamaInvest ⟷ External System
```
- يحتاج conflict resolution
- Last-Write-Wins
- أو merge logic

### Pattern 4: ETL (Batch)
**الاستخدام:** Daily/weekly bulk transfers
```
1. Extract from source
2. Transform to NamaInvest format
3. Load via bulk API
```

## 📝 Best Practices للـ Integrations

### للمطوّر الخارجي:
1. ✅ احفظ الـ API key بأمان (environment variable)
2. ✅ Use HTTPS only
3. ✅ Verify webhook signatures
4. ✅ Implement retry logic
5. ✅ Handle rate limits gracefully
6. ✅ Use idempotency keys
7. ✅ Log everything
8. ✅ Monitor your integration
9. ❌ لا تـ hardcode الـ secrets
10. ❌ لا تـ skip the signature check

### للمطوّر الداخلي:
1. ✅ Webhook subscriptions منظمة per tenant
2. ✅ Rate limiting صارم على الـ webhooks
3. ✅ Disable on repeated failures
4. ✅ Document every event
5. ✅ Versioning للـ payload schema

## 🔐 Security Considerations

### للـ API Keys:
- ✅ Scopes minimal (least privilege)
- ✅ Expiry dates
- ✅ IP restrictions (إذا possible)
- ✅ Rotation regularly
- ✅ Audit logs لكل request
- ❌ لا تشاركها

### للـ Webhooks:
- ✅ HMAC signatures
- ✅ Timestamp validation (anti-replay)
- ✅ HTTPS only
- ✅ Rate limiting
- ❌ لا تـ trust the payload بدون verify
